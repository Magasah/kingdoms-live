About this notice

KINGDOMS LIVE is a Windows desktop battle game designed for interactive LIVE streaming. This notice describes the game and its accompanying website. The current build uses a local simulator; production TikTok LIVE access is not connected. Any future authorized integration must be checked against this notice before release.

Information the game may receive

An authorized LIVE provider may supply a viewer display name or username, a stable provider user identifier, event identifiers and categories, gift identifiers and names, repeat counts, timestamps, team commands and limited interaction metadata. The game does not require a profile lookup when a name is already present. Ordinary comments are ignored for gameplay; optional supported team commands may update session membership. Likes may be counted in aggregate, with gameplay effects disabled by default.

How information is used

Data is used to resolve a viewer’s team, summon configured units, show a username and a short announcement, prevent duplicate events, troubleshoot service issues and protect the game against abuse. The operator must document the applicable legal basis before publication: [APPLICABLE LEGAL BASIS AND OPERATOR ASSESSMENT]. No advertising profiles or data-sale feature are implemented in this build.

Information we do not collect

The game does not collect account passwords, extract browser cookies, store TikTok login credentials or collect payment card information. It does not independently process TikTok payments. An authorized integration may require application-level access credentials, held outside the published source and never displayed in the game UI. These are distinct from a viewer’s password.

Local storage and retention

Viewer-to-team associations and the recent event monitor are held for the current application session. The router retains a bounded in-memory history of the latest 8,192 accepted event keys. Closing the game ends this session storage. Game settings and gift-to-action mappings persist locally until changed or deleted; mappings contain gift identifiers and names, not a required list of viewers. A rotating provider log stores connection and diagnostic information and unknown gift identifiers/names, with an approximate 512 KiB file plus one backup. The software does not promise an age-based deletion deadline for these files. The operator should remove unneeded logs and choose a documented maximum retention period: [DIAGNOSTIC RETENTION PERIOD]. Separately created screenshots, recordings or support exports may remain until their owner removes them.

Public stream display and recipients

A gift-spawned unit may display a viewer’s supplied username and a notification in the stream. If the streamer broadcasts or records the game, the streaming platform and its audience may see that information. The operator should explain this in their stream notice. Authorized event services, streaming platforms and any hosting or support providers process data under their own terms. The operator must identify deployed service providers and any relevant cross-border safeguards: [SERVICE PROVIDERS / LOCATIONS / TRANSFER SAFEGUARDS, IF APPLICABLE].

This website

The supplied static website contains no analytics scripts, advertising trackers, account registration or contact form. Its eventual hosting provider may process technical request information, such as an IP address, browser details and server logs, to serve and protect the website.
